About

What is Yourpropfirm Fanbasis?

Yourpropfirm Fanbasis is a WordPress plugin that connects your WooCommerce store to the Fanbasis platform. It adds Fanbasis as a selectable payment method at checkout, embedding the payment form directly inside your website so customers never leave your store to complete a purchase.

Once a customer pays, Fanbasis sends a real-time notification (webhook) to your store. The plugin validates it and automatically marks the WooCommerce order as completed, no manual action required.

ℹ️

Requirements WordPress 6.8+, WooCommerce, PHP 8.0+. No build tools or external dependencies needed.

Integration

Where Does This Plugin Fit?

This diagram shows how Yourpropfirm Fanbasis sits within the broader WooCommerce ecosystem, connecting the payment processor to the WooCommerce gateway layer, and feeding confirmed order status to the Yourpropfirm plugin for downstream processing.

Integration Area

WooCommerce · Fanbasis · Yourpropfirm Plugin connections

The store platform. Manages products, checkout, and order lifecycle. Yourpropfirm Fanbasis registers itself here as a payment gateway option.

Payment Flow

How a Payment Works

From the moment a customer adds a product to their cart to the order confirmation email, here is the complete journey.

Payment Process

Cart to Order Confirmation

1

Add to Cart & Checkout

Customer browses the store, adds a product, and proceeds to the WooCommerce checkout page.

2

Select Fanbasis Payment

Customer fills in billing details and selects Fanbasis as the payment method, then clicks Place Order.

3

Payment Form Opens

The Fanbasis payment form opens directly inside your website (popup modal or in-page). Billing details are pre-filled automatically, the customer only needs to enter their card details.

4

Payment is Processed

The customer submits the payment. Fanbasis processes it securely and returns a result.

5

Result: Success or Retry

Success: Fanbasis notifies your store via webhook. The plugin validates the payment and marks the order as Completed.

Failed: An error message appears inside the form. The customer can correct their details and try again without restarting checkout.

6

Order Confirmation

Customer is redirected to the WooCommerce order-received page and receives a confirmation email.

✅

Webhook confirmation happens automatically. There is no manual step, your store receives and validates the payment notification in the background, then updates the order status instantly.

Configuration

Checkout Methods

Choose how the Fanbasis payment form is presented to your customers. Both methods keep the customer on your website throughout the entire payment process.

Default

Embed - Popup Modal

The payment form opens as a full-screen overlay on the WooCommerce checkout page. No redirect, customer stays on the checkout page.

Best for

  • Standard WooCommerce themes
  • Fastest setup, no template files needed
  • Seamless experience without page navigation
Alternative

Embed - WC Order Pay Page

The payment form renders inside the native WooCommerce order-pay page, within your active store theme including header and footer.

Best for

  • Stores wanting full branding during payment
  • Optionally copy form-pay.php template into your theme
  • Works well with custom page builders

Limitations

Known Limitations

The following limitations apply to the current version of this plugin. Understanding these boundaries helps set the right expectations before integration.

🔌

WooCommerce Standard Integration

This plugin follows the WooCommerce payment gateway standard. The integration scope is limited to the payment flow: creating a temporary one-time payment product from the WooCommerce order, generating a Fanbasis checkout session (embedded via SDK iframe), processing payment, and verifying it via webhook. No customization outside this flow is included.

📦

Order Status Behavior

After payment is verified by Fanbasis webhook, the order status (Processing or Completed) depends on your WooCommerce configuration and any third-party plugins you use — for example, an auto-complete order plugin. Typically, once payment is verified, the order will be set to Processing or Completed based on those settings. The plugin itself sets the status to Completed upon successful webhook validation.

🔗

Post-Payment Third-Party Integration

Any business logic or provisioning that happens after payment (e.g. creating trading accounts, sending access credentials, triggering external services) is outside the scope of this plugin. These are handled by other Yourpropfirm plugins (Finpr, QTG) or third-party integrations that listen to WooCommerce order status changes.

📊

Marketing & Event Tracking

Event tracking integration (e.g. Google Tag Manager, GA4 — add-to-cart, begin checkout, purchase events, data layer) follows the WooCommerce standard and is handled by dedicated third-party plugins. This plugin does not implement or override any tracking events. For accurate purchase event firing, enable Wait for Payment Confirmation mode so the order is Completed before GTM fires the event.

💱

Currency — USD Only

Fanbasis currently only accepts USD as the payment currency. Multi-currency is not yet supported on the Fanbasis platform. This plugin does not include an automatic currency conversion feature, so your WooCommerce store must be configured with USD as the active currency for payments to work correctly.

🌐

Language — English Only

The Fanbasis checkout form and this plugin currently support English only. Multi-language and localization (i18n) are not yet supported. If your store uses a non-English locale, the Fanbasis payment form will still render in English.

💡

Limitations marked above reflect the current state of both this plugin and the Fanbasis platform. Some may be lifted in future releases as the Fanbasis API evolves.

Support

Frequently Asked Questions

How do I match a WooCommerce order with a Fanbasis transaction?
You can check the order detail page in WooCommerce. Under the Fanbasis Payment Info panel, you will find the following transaction data recorded from Fanbasis:
  • fan_product_id — Fanbasis product/session ID
  • fan_transaction_id — Fanbasis transaction history ID
  • fan_payment_id — Fanbasis payment ID
  • fan_payment_method — payment method used (e.g. card)

You can cross-reference these values with the transaction list in your Fanbasis Dashboard to verify and reconcile each payment.

Do I need to set up the webhook manually?
No. The plugin registers the Fanbasis webhook automatically when you save settings. You can check the registration status, environment, and webhook URL under Webhook Status on the settings page. The webhook is also re-registered automatically if you change your API key or switch environments.
Where can I view payment activity logs?
Go to WooCommerce → Status → Logs and filter by source yourpropfirm-fanbasis-debug. Make sure Enable Logs is turned on under Additional Settings. Use Advanced log mode when debugging, it shows full API payloads and responses.
Is the API key validated?
Yes. Every time you click Save changes on the settings page, the plugin sends a test request to the Fanbasis API to verify your key. If the key is invalid, an error message appears and settings are not saved.
Can I customise how the payment form looks?
Yes. The Styling Config section in settings gives you full control over the Fanbasis checkout form (theme, accent color, all color overrides, layout toggles), the popup modal (backdrop, container, header, spinner), and the processing overlay (enable/disable, background, spinner, text colors).
What order status is set after a successful payment?
When Fanbasis confirms payment via webhook, the plugin validates the amount, calls WooCommerce's payment_complete(), and sets the order status to Completed. An order note is automatically added with fan_product_id, fan_transaction_id, fan_payment_id, and validation_method: webhook. These values are also visible in the Fanbasis Payment Info panel on the order detail page.
What happens to the Fanbasis payment link after payment?
After a successful payment, the plugin automatically calls the Fanbasis API to delete the checkout session. This deactivates the payment link and prevents it from being reused for a duplicate charge.
